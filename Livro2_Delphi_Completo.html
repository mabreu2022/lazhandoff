1 APRESENTAÇÃO EDITORIAL E MANIFESTO DE ARQUITETURA

O ecossistema Delphi 12 Athens+ representa o estado da arte na engenharia de software de alta performance para ambientes corporativos e multiplataforma. Desde o surgimento do Delphi em 1995, o paradigma de desenvolvimento baseado em componentes (Component-Based Software Engineering - CBSE) tem sido a espinha dorsal de milhares de sistemas de missão crítica em bancos, hospitais, telecomunicações e indústrias globais.

No cenário tecnológico contemporâneo, no entanto, desenvolver componentes para Delphi exige uma abordagem muito mais sofisticada do que no passado. O desenvolvedor moderno precisa navegar pela coexistência de dois poderosos frameworks visuais:

  1. VCL (Visual Component Library): A biblioteca definitiva para o ecossistema Windows, agora totalmente equipada com High-DPI Per-Monitor v2, integração profunda com VCL Styles (incluindo Dark Mode dinâmico), renderização acelerada por Direct2D e compatibilidade absoluta com as últimas APIs do Windows 11.
  2. FireMonkey (FMX): O framework nativo multiplataforma acelerado por GPU (DirectX, Metal, OpenGL, Vulkan) projetado para Win32, Win64, macOS, iOS, Android e Linux, fundamentado em uma arquitetura vetorial e desacoplamento por estilos (TStyledControl).
  3. ToolsAPI Profunda (Open Tools API): A interface de integração que permite aos desenvolvedores transformarem o Delphi IDE, injetando Property Editors interativos, menus de contexto especializados, assistentes de projeto (Wizards) e geradores algorítmicos de código.
  4. Enhanced RTTI & Atributos Customizados: A moderna reflexão de código introduzida no Delphi, permitindo introspecção de tipos em tempo de execução sem penalidades de acoplamento.
  5. Acesso a Dados com FireDAC e TDataLink: A ponte de comunicação bidirecional de dados mais rápida do mercado, garantindo controles reativos a transações, estados de dataset e auditoria corporativa.

Este livro foi concebido como um compêndio de engenharia de software de alto nível. Cada um dos 25 módulos contém teoria aprofundada, diagramas conceituais claros e o código Pascal 100% completo, funcional e compilável de cada componente, com suporte a pacotes de tempo de execução (.dpk) e registro oficial na IDE.

5 MÓDULO 01: Arquitetura Orientada a Componentes e Hierarquia de Classes

No Delphi 12 Athens+, o desenvolvimento de componentes atingiu um patamar de maturidade e sofisticação sem precedentes. O arquiteto de software Object Pascal opera hoje na interseção entre duas grandes bibliotecas visuais — a tradicional e ultraotimizada VCL (Visual Component Library) para Windows e o revolucionário framework multiplataforma acelerado por hardware FireMonkey (FMX) —, amparadas por um dos compiladores nativos mais velozes do mundo e um sistema moderno de Enhanced RTTI enriquecido por atributos customizados.

Neste módulo inaugural, analisaremos a espinha dorsal da hierarquia de classes do Delphi moderno, dissecaremos as semelhanças e contrastes radicais entre VCL e FireMonkey, e implementaremos um componente profissional de introspecção profunda baseado na RTTI contemporânea do Delphi 12.

5.1.1 1.1 O Núcleo Comum da RTL: TObject, TPersistent e TComponent

Independentemente de você estar projetando para VCL ou FireMonkey, as três primeiras classes da árvore são universais e idênticas:

  1. TObject (System): Raiz do universo Pascal. Alocada estritamente no Heap. Contém o ponteiro de 4/8 bytes no cabeçalho apontando para a VMT (Virtual Method Table). Define o ciclo primitivo Create / Destroy / Free, e os métodos de introspecção clássicos (ClassType, ClassName, InheritsFrom).
  2. TPersistent (System.Classes): Habilita explicitamente a diretiva de RTTI clássica ({$M+}). Introduz o contrato de cópia canônica profunda (Assign e AssignTo) e a capacidade de streaming customizado com DefineProperties.
  3. TComponent (System.Classes): O elemento atômico do desenvolvimento visual e não-visual no Delphi. Introduz o conceito de Ownership (AOwner), serialização para arquivos de formulário (.dfm e .fmx), flags de estado de tempo de design (ComponentState), e o sistema de cancelamento de referências cruzadas (Notification / FreeNotification).

5.2 2. A Evolução da RTTI: De TypInfo ao System.Rtti e Atributos Customizados

Historicamente, o Delphi dependia exclusivamente da unidade System.TypInfo, que disponibilizava funções procedurais em linguagem C de baixo nível (GetPropList, GetTypeData, GetPropInfo) restritas exclusivamente a métodos e propriedades marcados explicitamente como published.

A partir das versões modernas e consolidada com maestria no Delphi 12 Athens+, a Embarcadero introduziu e aperfeiçoou o framework Enhanced RTTI no namespace System.Rtti.

5.2.1 2.1 Por que a Enhanced RTTI Revolucionou o Delphi?

  1. Introspecção Completa: Não está limitada à seção published. Pode inspecionar campos, propriedades e métodos private, protected e public (conforme a diretiva {$RTTI}).
  2. Orientação a Objetos Pura: Substitui ponteiros opacos e estruturas C por classes ricas como TRttiContext, TRttiType, TRttiProperty, TRttiMethod e TRttiField.
  3. Atributos Customizados (TCustomAttribute): Capacidade de anotar classes, propriedades e métodos com metadados decorativos legíveis em tempo de execução, abrindo as portas para validação declarativa, serializadores JSON/ORM sem acoplamento e injeção de dependência moderna.

function TDlpTypeHierarchyInspector.GetClassAncestry(AInstance: TObject): TStrings;
var
  CurrentObj: TObject;
  CurrentClass: TClass;
  Depth: Integer;
  ShouldStop: Boolean;
begin
  Result := TStringList.Create;
  try
    CurrentObj := AInstance;
    if not Assigned(CurrentObj) then
      CurrentObj := FTargetComponent;

    if not Assigned(CurrentObj) then
    begin
      Result.Add('Nenhum componente ou objeto selecionado para inspeção.');
      Exit;
    end;

    CurrentClass := CurrentObj.ClassType;
    Depth := 0;

    while Assigned(CurrentClass) do
    begin
      Result.Add(Format('[Nível %d] %s (Endereço VMT: %p)',
        [Depth, CurrentClass.ClassName, Pointer(CurrentClass)]));

      if Assigned(FOnClassNodeFound) then
        FOnClassNodeFound(Self, CurrentClass.ClassName, CurrentClass, Depth);

      Inc(Depth);

      ShouldStop := False;
      case FInspectionDepth of
        idImmediateOnly:
          ShouldStop := True;
        idUntilComponent:
          if CurrentClass = TComponent then
            ShouldStop := True;
        idFullToTObject:
          if CurrentClass = TObject then
            ShouldStop := True;
      end;

      if ShouldStop then
        Break;

      CurrentClass := CurrentClass.ClassParent;
    end;
  except
    on E: Exception do
      Result.Add('Falha durante introspecção de classe: ' + E.Message);
  end;
end;

function TDlpTypeHierarchyInspector.GetExtendedProperties(AInstance: TObject): TDlpPropertyExtendedMetaArray;
var
  CurrentObj: TObject;
  RttiContext: TRttiContext;
  RttiType: TRttiType;
  RttiProp: TRttiProperty;
  RttiAttr: TCustomAttribute;
  List: TList<TDlpPropertyExtendedMeta>;
  Meta: TDlpPropertyExtendedMeta;
  AttrSb: TStringBuilder;
  I: Integer;
begin
  CurrentObj := AInstance;
  if not Assigned(CurrentObj) then
    CurrentObj := FTargetComponent;

  if not Assigned(CurrentObj) then
  begin
    SetLength(Result, 0);
    Exit;
  end;

  List := TList<TDlpPropertyExtendedMeta>.Create;
  AttrSb := TStringBuilder.Create;
  try
    RttiContext := TRttiContext.Create;
    try
      RttiType := RttiContext.GetType(CurrentObj.ClassType);
      if Assigned(RttiType) then
      begin
        for RttiProp in RttiType.GetProperties do
        begin
          if (not FIncludePrivateProps) and (RttiProp.Visibility in [mvPrivate, mvProtected]) then
            Continue;

          Meta.PropName := RttiProp.Name;
          if Assigned(RttiProp.PropertyType) then
            Meta.TypeName := RttiProp.PropertyType.Name
          else
            Meta.TypeName := 'UnknownType';

          Meta.Visibility := VisibilityToString(RttiProp.Visibility);
          Meta.IsReadable := RttiProp.IsReadable;
          Meta.IsWritable := RttiProp.IsWritable;

          { Inspeciona Atributos Customizados da propriedade }
          AttrSb.Clear;
          Meta.CustomAttributeCount := Length(RttiProp.GetAttributes);
          for RttiAttr in RttiProp.GetAttributes do
          begin
            if AttrSb.Length > 0 then
              AttrSb.Append(', ');
            AttrSb.Append(RttiAttr.ClassName);
          end;
          Meta.AttributesSummary := AttrSb.ToString;

          List.Add(Meta);

          if Assigned(FOnPropertyInspected) then
            FOnPropertyInspected(Self, Meta);
        end;
      end;
    finally
      RttiContext.Free;
    end;

    Result := List.ToArray;
  finally
    AttrSb.Free;
    List.Free;
  end;
end;

function TDlpTypeHierarchyInspector.GenerateMarkdownDocumentation(AInstance: TObject): string;
var
  CurrentObj: TObject;
  Ancestry: TStrings;
  Props: TDlpPropertyExtendedMetaArray;
  SB: TStringBuilder;
  I: Integer;
  RttiContext: TRttiContext;
  RttiType: TRttiType;
  RttiAttr: TCustomAttribute;
begin
  CurrentObj := AInstance;
  if not Assigned(CurrentObj) then
    CurrentObj := FTargetComponent;

  if not Assigned(CurrentObj) then
    Exit('**Erro**: Nenhum componente ou objeto alvo atribuído.');

  SB := TStringBuilder.Create;
  Ancestry := nil;
  try
    SB.AppendLine(Format('### Documentação Técnica RTTI: `%s`', [CurrentObj.ClassName]));
    SB.AppendLine('');

    { Exibe atributos customizados da própria classe }
    RttiContext := TRttiContext.Create;
    try
      RttiType := RttiContext.GetType(CurrentObj.ClassType);
      if Assigned(RttiType) then
      begin
        SB.AppendLine('#### Atributos da Classe:');
        for RttiAttr in RttiType.GetAttributes do
        begin
          if RttiAttr is ComponentDocAttribute then
          begin
            SB.AppendLine(Format('- **Descricão**: %s (Versão: `%s`)',
              [ComponentDocAttribute(RttiAttr).Description, ComponentDocAttribute(RttiAttr).Version]));
          end
          else
          begin
            SB.AppendLine(Format('- **Atributo**: `%s`', [RttiAttr.ClassName]));
          end;
        end;
        SB.AppendLine('');
      end;
    finally
      RttiContext.Free;
    end;

    SB.AppendLine('#### 1. Árvore Genealógica de Herança:');

6 MÓDULO 02: O Ciclo de Vida Completo do Componente

A estabilidade de qualquer suíte profissional de componentes no Delphi 12 Athens+ repousa sobre a compreensão milimétrica do ciclo de vida dos seus objetos. Desenvolvedores que desconhecem os estágios exatos de transição de estado frequentemente enfrentam anomalias desconcertantes: propriedades que revertem para valores padrão, componentes que falham ao serem colados na superfície do formulário, exceções misteriosas durante a carga do executável e, o pior de todos os pesadelos RAD: violações de acesso (Access Violation in module coreide.bpl) que derrubam a própria IDE ao deletar um componente com o mouse.

Neste módulo, realizaremos um mergulho profundo no pipeline de vida dos componentes Delphi, contrastando a inicialização da VCL e do FireMonkey (FMX), dissecando o subsistema de notificações cruzadas e implementando um contêiner com vinculação fraca totalmente imune a dangling pointers.

6.2 2. As Fases Críticas de Vida e Suas Armadilhas

6.2.1 2.1 Construtor: Create(AOwner: TComponent)

No momento da execução do construtor: - A instância foi alocada pelo operador NewInstance. - O parâmetro AOwner passa a ser o tutor do ciclo de vida. Se AOwner for fornecido, nosso componente será inserido na lista interna de componentes do proprietário (FComponents: TList<TComponent>) e será automaticamente destruído quando o Owner for finalizado. - Armadilha Fatal na VCL: Nunca acesse a propriedade Handle, métodos de desenho do Canvas ou propriedades dependentes de janela no construtor. Ao ler a propriedade Handle prematuramente, o método getter GetHandle verifica que o handle ainda não existe e invoca compulsoriamente HandleNeeded → CreateHandle → CreateWnd. Isso força a alocação de um HWND no Windows antes mesmo do componente receber um Parent, resultando em janelas órfãs flutuantes ou falhas no DFM.

6.2.2 2.2 O Pós-Carregamento: procedure Loaded; override;

Quando um formulário é carregado do arquivo .dfm (seja em tempo de design ou durante a inicialização da aplicação), as propriedades são escritas na ordem em que foram salvas no arquivo. - Se a propriedade BorderColor depender da propriedade Color, e BorderColor for lida primeiro no arquivo de texto, qualquer validação no método assessor SetBorderColor falhará se tentar avaliar Color. - O método Loaded é o local canônico do Object Pascal para: 1. Realizar validações cruzadas entre propriedades dependentes. 2. Ajustar layouts complexos que exigem que todos os componentes vizinhos já estejam instanciados. 3. Notificar o subsistema visual de que os dados estão prontos.

6.2.3 2.3 A Materialização da Janela: CreateWnd e DestroyWnd

Diferente de frameworks puramente abstratos, a VCL mantém uma correspondência direta com a arquitetura de janelas da API do Windows: - procedure CreateWnd; override;: Invocado assim que o HWND é fisicamente criado pela função CreateWindowEx da API do Windows. Aqui é seguro chamar rotinas da Win32 API, inicializar timers nativos ou integrar controles com a DWM (Desktop Window Manager) do Windows 11. - procedure DestroyWnd; override;: Executado imediatamente antes do fechamento do HWND. Recursos da API do Windows associados exclusivamente ao identificador de janela devem ser finalizados aqui.

6.2.4 2.4 Ciclo de Vida no FireMonkey: O Papel de ApplyStyle

No FireMonkey (FMX), o paradigma é substancialmente diferente: - A maioria dos controles não cria HWND nativo (apenas a janela raiz possui handle). - O equivalente conceitual de CreateWnd no FMX é o método virtual: pascal procedure ApplyStyle; override; - No FMX, o controle visual herda de TStyledControl. Ao ser instanciado e colocado em um container com estilo ativo, a engine do FireMonkey procura no arquivo de estilo (.style) a estrutura vetorial correspondente a StyleLookup. O método ApplyStyle é invocado para localizar e vincular objetos filhos do estilo (como sub-painéis, shapes e animações com FindStyleResource).

6.3 3. O Mapa Completo de Flags: ComponentState e ControlState

O estado interno de um componente no Delphi é monitorado por duas propriedades fundamentais:

6.4 4. O Mal das Referências Cruzadas e a Solução FreeNotification

No desenvolvimento de componentes avançados, é rotina expor propriedades que apontam para outros componentes existentes no formulário (por exemplo: um botão apontando para um menu popup, um label apontando para um edit, ou um painel apontando para um controle parceiro).

Se você simplesmente salvar o ponteiro em uma variável privada:

// CÓDIGO INSEGURO / AMADOR
procedure TMeuComponente.SetAlvo(const AValue: TControl);
begin
  FAlvo := AValue;
end;

Quando o usuário seleciona o componente apontado no designer e o deleta, a variável FAlvo se torna um dangling pointer (aponta para uma região de memória que não existe mais). Qualquer tentativa posterior de ler FAlvo.Name ou chamar um método virtual resultará em uma falha fatal que fecha o Delphi IDE ou corrompe o projeto.

6.4.1 O Protocolo Definitivo de Vinculação Segura:

[Seu Componente]                                      [Componente Alvo]
       |                                                      |
       |--- 1. SetTarget(TargetInstance) -------------------->|
       |--- 2. TargetInstance.FreeNotification(Self) -------->| (Inscreve na lista interna)
       |                                                      |
       |             ... Ciclo normal de trabalho ...         |
       |                                                      |
       |                                  [Usuário deleta o Componente Alvo]
       |                                                      |
       |<-- 3. Notification(Self, opRemove) ------------------| (Avisa antes de desalocar!)
       |                                                      |
       +--- 4. FTarget := nil; Invalidate; -------------------+

Ao registrar FreeNotification, garantimos que, no instante em que o alvo for destruído, ele primeiro notificará todos os observadores, permitindo que nosso componente anule a referência com total segurança.

    Canvas.MoveTo(0, FHeaderHeight);
    Canvas.LineTo(Width, FHeaderHeight);

      R, DT_LEFT or DT_VCENTER or DT_SINGLELINE);
  end;

  { 3. Renderização do Destaque de Vínculo }
  if Assigned(FLinkedControl) and (FLinkStatusStyle <> lssNone) then
  begin
    LinkInfo := Format('LINK: %s (%s)', [FLinkedControl.Name, FLinkedControl.ClassName]);
    Canvas.Font.Size := 8;
    Canvas.Font.Style := [fsBold];

    if FLinkStatusStyle = lssBadge then
    begin
      BadgeR := Rect(Width - 160, 4, Width - 8, FHeaderHeight - 4);
      Canvas.Brush.Color := $00336600; // Verde corporativo

7 MÓDULO 03: Mecanismo de Streaming e Persistência (DFM)

O subsistema de Streaming DFM do Delphi é um dos pilares mais elegantes já concebidos na história da engenharia de software. Desde os primórdios da VCL até o moderno Delphi 12 Athens+, o mecanismo que converte uma árvore viva de objetos em memória em uma representação serializada (e vice-versa) opera de maneira silenciosa, altamente otimizada e reflexiva.

Contudo, desenvolver componentes corporativos exige ir muito além das propriedades nativas simples. Frequentemente precisamos armazenar no arquivo .dfm coleções genéricas (TDictionary<K, V>), configurações criptografadas, chaves de API ofuscadas ou buffers de dados complexos que a RTTI padrão não consegue mapear automaticamente.

Neste módulo, dissecaremos o funcionamento interno do subsistema TFiler, TReader e TWriter no Delphi 12, analisaremos o ciclo de vida do DFM textual e binário, dominaremos os especificadores stored para máxima performance de inicialização e implementaremos um repositório seguro de dados serializado via DefineProperties.

7.1.1 1.1 DFM Textual vs. DFM Binário

No Delphi moderno, o formulário é manipulado no editor em formato texto (legível em sistemas de controle de versão como Git):

Durante a compilação do executável ou pacote (.dpk), o compilador do Delphi compila a diretiva {$R *.dfm}, transformando o texto em um fluxo binário compacto composto por bytes de cabeçalho ($FF, $0A), tokens de tipo (vaInt8, vaString, vaBinary) e identificadores de classe.

Quando a aplicação executa em produção, a VCL/FMX não lê arquivos de texto: ela carrega o recurso binário compilado diretamente do segmento de recursos do Windows PE (HINSTANCE), garantindo tempos de inicialização na ordem de milissegundos.

7.2 2. A Matriz de Tipos e a Persistência Automática

Para que uma propriedade seja serializada automaticamente pelo TWriter do Delphi, dois requisitos são obrigatórios: 1. Deve estar sob a visibilidade published. 2. Deve possuir tanto leitor (read) quanto escritor (write).

Tipo de Dado Pascal Como o Delphi 12 Serializa no DFM
Inteiros / Enums Gravado diretamente pelo valor ordinal ou pelo identificador textual do enum (ex: Align = alClient).
Strings / Caracteres Gravado como texto entre aspas simples. Quebras de linha e caracteres de controle são gravados como #13#10.
Pontos Flutuantes Gravados em representação de alta precisão.
Sets (Conjuntos) Gravados entre colchetes como lista de identificadores (ex: Anchors = [akLeft, akTop]).
Sub-Objetos TPersistent O TWriter desce recursivamente na hierarquia e grava todas as propriedades published do sub-objeto (ex: Font.Name, Font.Size).
Coleções TCollection Gravado como bloco delimitado contendo os itens tipados indexados.
Componentes (TComponent) Gravado como o nome literal do componente parceiro (ex: LinkedControl = Edit1).

7.3 3. Otimização de Arquivo: O Poder do Especificador stored

Um dos maiores erros cometidos por desenvolvedores Delphi novatos é deixar propriedades publicadas sem cláusula default.

Quando uma propriedade inteira não possui default:

published
  property Padding: Integer read FPadding write FPadding; // SEM DEFAULT

O TWriter é forçado a gravar Padding = 0 em todos os arquivos .dfm do projeto. Multiplique isso por 500 telas e você terá megabytes de texto inútil no repositório Git e centenas de ciclos de CPU desperdiçados no carregamento.

7.3.1 3.1 Declarando o Valor default

published
  property Padding: Integer read FPadding write FPadding default 8;

Se Padding for igual a 8, o TWriter consulta a RTTI, constata que o valor em memória coincide com o default e ignora completamente a propriedade no DFM.

7.3.2 3.2 O Modificador stored Dinâmico

Para tipos que não suportam constantes literais (como string ou classes), o Delphi permite associar uma função booleana ao especificador stored:

private
  function IsSecretKeyStored: Boolean;
published
  property SecretKey: string read FSecretKey write SetSecretKey stored IsSecretKeyStored;

7.4 4. Persistência Customizada de Estruturas Não-Nativas: DefineProperties

Coleções genéricas como TDictionary<string, string>, listas encadeadas ou matrizes de ponto flutuante não podem ser declaradas na seção published porque o compilador não gera informações clássicas de RTTI para tipos genéricos abertos.

Como salvar um dicionário inteiro de parâmetros dentro do .dfm? A resposta é sobrescrever o método protegido da raiz TPersistent:

procedure DefineProperties(Filer: TFiler); override;

O TFiler oferece o método DefineBinaryProperty:

Filer.DefineBinaryProperty('EncryptedPayload', ReadEncryptedPayload, WriteEncryptedPayload, HasEntriesToStore);

7.4.1 O Funcionamento do Streaming Binário Virtual:

  1. Em Tempo de Gravação (Design-Time ou Compilação): O TWriter invoca DefineProperties. Se a condição booleana HasEntriesToStore for verdadeira, o Delphi abre um bloco com o nome virtual 'EncryptedPayload' e invoca o callback WriteEncryptedPayload(AStream).
  2. Em Tempo de Leitura (Runtime / Carga do Form): O TReader encontra o bloco 'EncryptedPayload', invoca o callback ReadEncryptedPayload(AStream) e nos entrega um stream contendo exatamente os bytes persistidos.
  3. No arquivo .dfm textual, o Delphi formata automaticamente esses bytes em blocos hexadecimais protegidos por chaves { ... }.

procedure TDlpEncryptedDataStore.ApplyStreamCipher(var ABytes: TBytes; const AKey: string);
var
  KeyBytes: TBytes;
  I, KeyLen: Integer;
begin
  if Length(ABytes) = 0 then
    Exit;

  KeyBytes := TEncoding.UTF8.GetBytes(AKey);
  KeyLen := Length(KeyBytes);
  if KeyLen = 0 then
    Exit;

  for I := 0 to High(ABytes) do
    ABytes[I] := ABytes[I] xor KeyBytes[I mod KeyLen] xor Byte((I * 37) and $FF);
end;

procedure TDlpEncryptedDataStore.ReadEncryptedPayload(AStream: TStream);
var
  EntryCount, I: Integer;
  IsEncryptedFlag: Byte;
  KeyStr, ValStr: string;
  KeyBytes, ValBytes: TBytes;
  KeyLen, ValLen: Integer;
  PayloadSize: Int64;
begin
  FStore.Clear;

  PayloadSize := AStream.Size - AStream.Position;
  if PayloadSize <= 0 then
    Exit;

  FLastPersistedBytes := PayloadSize;

  { 1. Lê a flag de criptografia }
  AStream.ReadBuffer(IsEncryptedFlag, SizeOf(Byte));
  { 2. Lê a quantidade de registros }
  AStream.ReadBuffer(EntryCount, SizeOf(Integer));

  for I := 0 to EntryCount - 1 do
  begin
    { Lê a Chave }
    AStream.ReadBuffer(KeyLen, SizeOf(Integer));
    SetLength(KeyBytes, KeyLen);
    if KeyLen > 0 then
      AStream.ReadBuffer(KeyBytes[0], KeyLen);

    { Lê o Valor }
    AStream.ReadBuffer(ValLen, SizeOf(Integer));
    SetLength(ValBytes, ValLen);
    if ValLen > 0 then
      AStream.ReadBuffer(ValBytes[0], ValLen);

    { Decifra os bytes se aplicável }
    if IsEncryptedFlag = 1 then
    begin
      ApplyStreamCipher(KeyBytes, FSecretKey);
      ApplyStreamCipher(ValBytes, FSecretKey);
    end;

    KeyStr := TEncoding.UTF8.GetString(KeyBytes);
    ValStr := TEncoding.UTF8.GetString(ValBytes);

    FStore.AddOrSetValue(KeyStr, ValStr);
  end;

  DoChanged;
end;

procedure TDlpEncryptedDataStore.WriteEncryptedPayload(AStream: TStream);
var
  Pair: TPair<string, string>;
  EntryCount: Integer;
  IsEncryptedFlag: Byte;
  KeyBytes, ValBytes: TBytes;
  KeyLen, ValLen: Integer;
  StartPos: Int64;
begin
  if not HasEntriesToStore then
    Exit;

  StartPos := AStream.Position;

  { 1. Escreve a flag de criptografia e a contagem de pares }
  if FAutoEncrypt then
    IsEncryptedFlag := 1
  else
    IsEncryptedFlag := 0;

  AStream.WriteBuffer(IsEncryptedFlag, SizeOf(Byte));

  EntryCount := FStore.Count;
  AStream.WriteBuffer(EntryCount, SizeOf(Integer));

  { 2. Itera gravando cada par chave/valor com proteção criptográfica }
  for Pair in FStore do
  begin
    KeyBytes := TEncoding.UTF8.GetBytes(Pair.Key);
    ValBytes := TEncoding.UTF8.GetBytes(Pair.Value);

    if FAutoEncrypt then
    begin
      ApplyStreamCipher(KeyBytes, FSecretKey);
      ApplyStreamCipher(ValBytes, FSecretKey);
    end;

    KeyLen := Length(KeyBytes);
    AStream.WriteBuffer(KeyLen, SizeOf(Integer));
    if KeyLen > 0 then
      AStream.WriteBuffer(KeyBytes[0], KeyLen);

    ValLen := Length(ValBytes);
    AStream.WriteBuffer(ValLen, SizeOf(Integer));
    if ValLen > 0 then
      AStream.WriteBuffer(ValBytes[0], ValLen);
  end;

  FLastPersistedBytes := AStream.Position - StartPos;
end;

8 MÓDULO 04: Tratamento de Mensagens do SO e Arquitetura de Eventos

A interface gráfica do Windows é um sistema puramente guiado por mensagens (Message-Driven Architecture). No Delphi 12 Athens+, a VCL encapsula a complexidade do loop de mensagens Win32/64 com uma elegância inigualável através do método virtual WndProc e da sintaxe de métodos de mensagem message WM_*.

8.1 1. O Pipeline de Mensagens do Windows na VCL

Ao emitir ou propagar mensagens no Delphi, existem quatro rotas com comportamentos operacionais diametralmente distintos:

Mecanismo de Despacho Como Executa Cruza a Fila do SO? Retorna Imediatamente? Risco de Deadlock
Perform(Msg, WParam, LParam) Chama diretamente a WndProc do objeto Pascal em memória. Não. É uma chamada de método Pascal pura O(1). Não (é síncrono). Baixo (a menos que haja reentrância).
SendMessage(HWND, Msg, ...) Invoca a API do Windows. A thread aguarda o retorno da janela de destino. Sim. Cruza o subsistema do SO. Não (bloqueia o emissor até a resposta). Alto (se a janela de destino estiver bloqueada pela thread emissora).
PostMessage(HWND, Msg, ...) Deposita a mensagem na fila da janela do Windows e retorna instantaneamente. Sim. Sim (assíncrono). Quase nulo.
TThread.Queue(nil, AnonProc) Agenda uma rotina anônima na fila da UI thread do Delphi. Não passa pelo Win32, opera no subsistema da RTL. Sim (desacoplamento assíncrono). Zero (a thread de fundo nunca é bloqueada).

8.3 3. Subclassing Dinâmico de Janelas na VCL

Quando criamos um componente derivado de TWinControl (como um botão ou painel), podemos interceptar mensagens declarando métodos com a palavra reservada message:

procedure WMKeyDown(var Message: TWMKeyDown); message WM_KEYDOWN;

Porém, quando desenvolvemos um componente não-visual utilitário (como um logger de ações, um validador de formulário ou um assistente de atalhos globais), precisamos interceptar mensagens de um TForm ou TEdit já colocado na tela.

A VCL disponibiliza uma propriedade extraordinária em todo TWinControl:

property WindowProc: TWndMethod read FWindowProc write FWindowProc;

Onde TWndMethod é o delegate canônico:

TWndMethod = procedure(var Message: TMessage) of object;

Ao substituir temporariamente o WindowProc do alvo pelo nosso método, obtemos controle absoluto sobre todas as mensagens que chegam ao controle antes que a VCL as processe. Se nossa lógica marcar MsgInfo.Handled := True, a mensagem é abortada na raiz.

8.4 4. Modern Event Architecture: Delegates Clássicos vs. Métodos Anônimos

O Delphi 12 permite unificar a arquitetura de eventos tradicional com closures modernos.

8.4.1 4.1 O Formato Clássico: of object

TOnWindowsMessageIntercepted = procedure(Sender: TObject; var AMsgInfo: TDlpMessageInfo) of object;

Permite ligação direta no Object Inspector em tempo de design.

8.4.2 4.2 Métodos Anônimos com Captura de Escopo (Closures)

TDlpAsyncMessageCallback = reference to procedure(const AToken: Int64; const APayload: string);

Permite que o desenvolvedor passe blocos de código inline no momento exato do disparo:

Interceptor.QueueAnonymousCallback(
  procedure(const AToken: Int64; const APayload: string)
  begin
    ShowMessage(Format('Notificação %d recebida: %s', [AToken, APayload]));
  end, 'Dados do Sensor');

As variáveis locais capturadas pelo método anônimo têm seu tempo de vida gerenciado automaticamente pela RTL através de interfaces ocultas geradas pelo compilador.

    DetachSubclass;

  if FActive <> AValue then
  begin
    FActive := AValue;

    begin
      if FActive then
        AttachSubclass
      else
        DetachSubclass;
    end;
  end;
end;

procedure TDlpWindowsMessageInterceptor.AttachSubclass;
begin
  if csDesigning in ComponentState then
    Exit;

  if Assigned(FTargetControl) and (FOriginalWindowProc = nil) then
  begin
    FOriginalWindowProc := FTargetControl.WindowProc;
    FTargetControl.WindowProc := InterceptorWindowProc;
  end;
end;

procedure TDlpWindowsMessageInterceptor.DetachSubclass;
begin
  if Assigned(FTargetControl) and Assigned(FOriginalWindowProc) then
  begin
    FTargetControl.WindowProc := FOriginalWindowProc;
    FOriginalWindowProc := nil;
  end;
end;

procedure TDlpWindowsMessageInterceptor.Notification(AComponent: TComponent; Operation: TOperation);
begin
  inherited Notification(AComponent, Operation);
  if (Operation = opRemove) and (AComponent = FTargetControl) then
  begin
    FOriginalWindowProc := nil;
    FTargetControl := nil;
  end;
end;

procedure TDlpWindowsMessageInterceptor.InterceptorWindowProc(var Message: TMessage);
var
  MsgInfo: TDlpMessageInfo;
  ShouldIntercept: Boolean;
begin
  ShouldIntercept := False;

  if FInterceptKeyboard and (Message.Msg in [WM_KEYDOWN, WM_KEYUP, WM_CHAR, WM_SYSKEYDOWN, WM_SYSKEYUP]) then
    ShouldIntercept := True;

  if FInterceptMouse and (Message.Msg in [WM_LBUTTONDOWN, WM_RBUTTONDOWN, WM_MOUSEMOVE, WM_MOUSEWHEEL]) then
    ShouldIntercept := True;

  if FInterceptSystem and (Message.Msg in [WM_SYSCOMMAND, WM_COMMAND, WM_SETFOCUS, WM_KILLFOCUS]) then
    ShouldIntercept := True;

  if ShouldIntercept and Assigned(FOnMessageIntercepted) then
  begin
    MsgInfo.Msg := Message.Msg;
    MsgInfo.WParam := Message.WParam;
    MsgInfo.LParam := Message.LParam;
    MsgInfo.Handled := False;
    MsgInfo.Result := 0;
    MsgInfo.Timestamp := Now;

    try
      FOnMessageIntercepted(Self, MsgInfo);
    except
      { Isola o pipeline de janelas contra exceções em código do consumidor }
    end;

    if MsgInfo.Handled then
    begin
      Message.Result := MsgInfo.Result;
      Exit;
    end;
  end;

  { Se não interceptada ou Handled = False, repassa para a WindowProc original }
  if Assigned(FOriginalWindowProc) then
    FOriginalWindowProc(Message);
end;

procedure TDlpWindowsMessageInterceptor.QueueAsyncNotification(const APayload: string);
var
  CurrentToken: Int64;
  SavedPayload: string;
begin
  if not Assigned(FOnAsyncDispatched) then
    Exit;

  Inc(FSequenceToken);
  CurrentToken := FSequenceToken;
  SavedPayload := APayload;

  { Enfileira de forma assíncrona na UI thread sem risco de deadlocks }
  TThread.Queue(nil,
    procedure
    begin
      if Assigned(FOnAsyncDispatched) and not (csDestroying in ComponentState) then
        FOnAsyncDispatched(Self, CurrentToken, SavedPayload);
    end);
end;

procedure TDlpWindowsMessageInterceptor.QueueAnonymousCallback(
  ACallback: TDlpAsyncMessageCallback; const APayload: string);
var
  CurrentToken: Int64;
  SavedPayload: string;
  SavedCallback: TDlpAsyncMessageCallback;
begin
  if not Assigned(ACallback) then
    Exit;

  Inc(FSequenceToken);
  CurrentToken := FSequenceToken;
  SavedPayload := APayload;
  SavedCallback := ACallback;

  TThread.Queue(nil,
    procedure
    begin
      if not (csDestroying in ComponentState) then
        SavedCallback(CurrentToken, SavedPayload);
    end);
end;

end.

9.1.1 1.1 As Diretivas de Compilação Críticas: {$RUNONLY} e {$DESIGNONLY}

  1. {$RUNONLY} no Pacote de Runtime:
    • Sinaliza à IDE do Delphi que esse pacote contém exclusivamente código executável da aplicação.
    • O Delphi proíbe terminantemente que um pacote marcado como {$RUNONLY} seja instalado diretamente na Tool Palette da IDE.
    • Isso impede que o desenvolvedor acidentalmente tente registrar componentes ou vincular editores de propriedade dentro do pacote de runtime.
  2. {$DESIGNONLY} no Pacote de Design-Time:
    • Sinaliza que o pacote se destina exclusivamente à IDE (bds.exe).
    • O compilador bloqueia que projetos finais de clientes adicionem o pacote de design-time na lista de pacotes de runtime do executável.
    • Apenas o pacote de Design-Time deve conter requires designide;.

No ecossistema Delphi 12 Athens+, a VCL disponibiliza duas vias principais para criação de interfaces visuais: controles janelados pesados (TWinControl), que possuem um identificador nativo de janela (HWND), e controles gráficos leves (TGraphicControl), que operam sem handle (windowless).

13.1 1. O Funcionamento de TGraphicControl na VCL

Diferente de um TPanel ou TEdit, o TGraphicControl não consome recursos de janela do Windows:

20.2 2. Ação Automática sobre Transações Zumbis

O método CheckZombieTransactions pode ser acionado periodicamente (por exemplo, através de um TTimer de infraestrutura ou na rotina de fechamento de formulários). Caso detecte uma transação estagnada, ele notifica a aplicação via evento e, se a flag AutoRollbackZombies estiver ativa, força o Rollback para liberar os locks no banco:

procedure TDlpDataConnectionMonitor.CheckZombieTransactions;
var
  AgeSec: Int64;
  ShouldRollback: Boolean;
begin
  if not FActive or not IsTransactionActive then
    Exit;

  AgeSec := GetTransactionAgeSeconds;
  if (AgeSec >= FMaxTransactionDurationSec) and (AgeSec > 0) then
  begin
    ShouldRollback := FAutoRollbackZombies;
    WriteLogEntry(Format('FIREDAC_ZOMBIE_TX_ALERT: Transação ativa por %d segundos.', [AgeSec]));

    if Assigned(FOnZombieTransactionDetected) then
      FOnZombieTransactionDetected(Self, FConnection, AgeSec, ShouldRollback);

    if ShouldRollback and FConnection.InTransaction then
    begin
      try
        FConnection.Rollback;
        FTxStartTime := 0;
        WriteLogEntry('FIREDAC_ZOMBIE_TX_ACTION: Rollback efetuado com sucesso.');
      except
        on E: Exception do
          WriteLogEntry('FIREDAC_ZOMBIE_TX_ERROR: Falha ao executar rollback: ' + E.Message);
      end;
    end;
  end;
end;

24.2 2. Aritmética Comercial: Margem de Lucro vs. Markup

A distinção precisa entre margem de lucro e markup é crucial para a integridade de qualquer sistema de gestão:

  • Margem de Lucro: Percentual de lucro obtido sobre o preço de venda final.
  • Markup: Coeficiente multiplicador aplicado sobre o preço de custo.

$$ \text{Margem (\%)} = \frac{\text{Preço Venda} - \text{Preço Custo}}{\text{Preço Venda}} \times 100 $$

$$ \text{Markup (\%)} = \frac{\text{Preço Venda} - \text{Preço Custo}}{\text{Preço Custo}} \times 100 $$

O componente TDlpProductStockIndicator fornece essas rotinas nativas:

class function TDlpProductStockIndicator.CalculateMargin(CostPrice, SellPrice: Double): Double;
begin
  if SellPrice <= 0 then
    Exit(0.0);
  Result := ((SellPrice - CostPrice) / SellPrice) * 100.0;
end;

class function TDlpProductStockIndicator.CalculateMarkup(CostPrice, SellPrice: Double): Double;
begin
  if CostPrice <= 0 then
    Exit(0.0);
  Result := ((SellPrice - CostPrice) / CostPrice) * 100.0;
end;

25.1.1 1.1 TThread.Synchronize vs. TThread.Queue

  • Synchronize: Interrompe (bloqueia) a thread de trabalho até que a thread principal desenhe a interface. Isso cria gargalos severos e pode provocar Deadlock caso a tela esteja aguardando o término da thread via TTask.Wait.

A função estática ParseToledoWeight filtra os dígitos e converte o valor diretamente em ponto flutuante:

class function TDlpSerialDeviceConnector.ParseToledoWeight(const ARaw: string): Double;
var
  CleanDigits: string;
  i, ValInt: Integer;
begin
  Result := 0.0;
  CleanDigits := '';
  for i := 1 to Length(ARaw) do
  begin
    if CharInSet(ARaw[i], ['0'..'9']) then
      CleanDigits := CleanDigits + ARaw[i];
  end;

  if Length(CleanDigits) >= 5 then
  begin
    CleanDigits := Copy(CleanDigits, Length(CleanDigits) - 4, 5);
    ValInt := StrToIntDef(CleanDigits, 0);
    Result := ValInt / 1000.0;
  end;
end;

procedure TDlpMqttClientBridge.ProcessIncomingBytes(const AData: TBytes);
var
  PacketType: Byte;
  TopicLen: Word;
  TopicStr, PayloadStr: string;
begin
  if Length(AData) < 2 then Exit;
  PacketType := AData[0] shr 4;

  case PacketType of
    2: { CONNACK }
      begin
        if (Length(AData) >= 4) and (AData[3] = 0) then
        begin
          FIsConnected := True;
          if Assigned(FOnConnectionChange) then
            FOnConnectionChange(Self, True, 'Conexao com broker MQTT confirmada.');
        end;
      end;

    3: { PUBLISH Recebido }
      begin
        if Length(AData) > 4 then
        begin
          TopicLen := (AData[2] shl 8) or AData[3];
          TopicStr := TEncoding.UTF8.GetString(AData, 4, TopicLen);
          PayloadStr := TEncoding.UTF8.GetString(AData, 4 + TopicLen, Length(AData) - (4 + TopicLen));
          if Assigned(FOnMessageReceived) then
            FOnMessageReceived(Self, TopicStr, PayloadStr, qosAtMostOnce, False);
        end;
      end;
  end;
end;

A similaridade por cosseno quantifica a coincidência de direção entre os dois vetores multidimensionais, variando no intervalo [ − 1.0,  + 1.0], onde valores próximos a  + 1.0 atestam afinidade semântica máxima:

function TDlpVectorEmbeddingStore.ComputeCosineSimilarity(const V1, V2: TDlpEmbeddingVector;
  Mag1, Mag2: Single): Single;
var
  Dot, Denominator: Single;
  i, Len: Integer;
begin
  Len := Length(V1);
  if (Len <> Length(V2)) or (Len = 0) then Exit(0.0);

  Dot := 0.0;
  for i := 0 to Len - 1 do
    Dot := Dot + (V1[i] * V2[i]);

  Denominator := Mag1 * Mag2;
  if Denominator > 0.000001 then
    Result := Dot / Denominator
  else
    Result := 0.0;
end;
